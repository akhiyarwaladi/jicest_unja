# Public files

Use lowercase filenames with hyphens for conference assets and documents, for example `nattinee-thongdee-2026.jpg` or `jicest-2026-presenter-guidelines.pdf`. Keep the real file extension.

```text
public/
  assets/
    css/                       Stylesheets, including vendor files
    fonts/                     Vendor fonts with their original filenames
    js/                        Scripts, including vendor files
    img/
      backgrounds/             Homepage and section backgrounds
      committees/              Organizing, scientific, and steering committee photos
      people/                  Rector, dean, and opening speaker photos
      publications/            Proceedings covers and QR images
      signatures/              Signature images used in generated PDFs
      speakers/                Keynote and invited speaker portraits
      stamps/                  Stamp images
      archive/                 Other historical images
    logos/                     Conference, university, bank, and partner logos
    vendor-archives/            Original ZIP packages, not runtime dependencies
  uploads/
    downloads/
      2026/                    Current abstract/paper templates and presenter guidelines
      proceedings/             Books of abstracts and conference publications
      speakers/                Speaker CVs and biographies
      archive/                 Previous templates, schedules, and other historical documents
    fulltext/                  Existing participant paper uploads
    images/                    Existing payment evidence
    invoice*/                  Existing generated invoices
    letter-of-acceptance*/     Existing acceptance letters
    receipt*/                  Existing receipts
    livewire-tmp/              Temporary application uploads
  build/                       Vite output; generated by the build process
  storage/                     Laravel storage link; managed by storage:link
```

Other existing image categories remain under `assets/img`. Historical variants are retained in their relevant `archive` folders.

Participant files keep their existing paths and filenames, including generated IDs and personal names. These paths may be stored in the database or used in previously issued emails and PDFs. Do not rename these files as part of an asset cleanup.

Keep framework entry points, `.htaccess`, verification files, `robots.txt`, `sitemap.xml`, and vendor font filenames unchanged. They follow external conventions.

## Existing URLs

`config/public-assets.php` records the old and new relative paths. Public routes issue a permanent redirect for each old URL, so previously shared static asset and document links continue to work. These explicit redirects do not handle participant uploads or arbitrary paths.

Application views and download handlers use the new paths directly. Download endpoints such as `/download-abstract-template` and `/download-guidelines-template` keep their existing URLs. `/download-schedule-template` shows the oral schedule's Coming soon page until a current schedule is available.

When deploying, include the renamed files, updated source, and redirect configuration together, then run `php artisan optimize:clear` to refresh cached configuration, routes, and views.
